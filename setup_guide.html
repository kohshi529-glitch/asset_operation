正典（pcanon）の運用

1置き場所と命名

Google Drive「SBI」フォルダに pcanon_{slug}_{YYYYMMDD_HHMM}.md を新規作成で置く。同じ slug のうち modifiedTime が最新のものが現行。上書き・削除はしない（過去版がそのまま履歴になる）。

2中身

先頭にヘッダ（slug・版・前版・正典作成日時・登録設定 = 名前/cron/環境/通知・変更点の理由）、続いて「プロンプト全文」を1つのコードブロックに通し版で書く。本文中に「★vX 新設」のような版マーカーは置かない（版を名乗るのは【版】行だけ。規則の理由は残す）。

3登録の検証

Drive の create_file が返す fileSize がローカルのバイト数と完全一致していることを確認する。機能マーカー（該当 STEP 名など）が含まれること、絵文字の異体字セレクタ（U+FE0F）が 0 件であることも確認する。

4正典が無いものは登録する

2026-09-15 時点で稼働中なのに正典が無いもの: ①-5 STF週次・戦績ボードPJ。登録画面・正典・実行ログの三点棚卸しをしてから登録する。保留中のもの（週末材料キャッチアップ＝長期保留、手法別スクリーニングPJ・SaaSカルテPJ＝ほぼ非稼働）は再開時に正典を作ってから登録する。①-10 は登録時の上書きでプロンプトが消えた実例。

指示文（タスク／PJ）の更新手順

1対話セッションに依頼する

「①-8 の ○○ を変えたい」と伝える。セッションは現行正典（または貼り付けた現行本文）を土台に通し版で書き直し、MD ファイルのコードブロックで全文を納品する。追記パッチやチャット本文への全文貼り付けはしない。

2あなたがタスクに反映する

登録画面のプロンプト欄を全文置換（追記ではない）。cron や名前の変更が指示されていればそれも合わせる。Cowork は勝手に反映しない。

3「反映完了」と伝える → 正典登録

セッションが Drive に pcanon を新規作成し fileSize 一致で検証する。ヘッダの正典作成日時は登録時刻に合わせる。

4翌夜の実行で確認

通知の【版】行と自己検証行（例: ①-8 なら「grades.json: … バイト」「verdicts: n件」）が新版のものになっているかを見る。pipeline.runs.*.memo にも版や entrance= が残る。

⚠ 閾値はタスク上で口頭調整しない

入口条件や減点幅などの数字は正典改訂でだけ変える。例: ①-S2 v1.2 の A転換 pre5≤+3%／hi20≤−2%、C リバ 25日乖離≤−8%、押し目×急落 −2 は暫定値で、V1〜V3（10月上旬）の再検証で確定する。

書き込み規約（全ルーティン共通）

1PR 方式のみ

自セッションのブランチに commit/push → main への PR を自動作成 → あなたが翌朝ワンタップでマージ。main への直接 push はしない（git プロキシも拒否する）。

2指定キー以外は1バイトも変えない

各ルーティンは自分のキー（例: ①-12 は watchlist だけ）にしか書かない。書き出し前後で他キーの同一性をプログラムで検証する。

3indent は検出して合わせる

indent 固定で書き出すと数万行が再整形され、同時発火の PR が必ず衝突する（PR#181）。既存 indent を検出し、git diff --numstat で差分行数を自己チェックする。

4push 直前に main を再取得する

ブランチ作成後に別 PR が入ると衝突する（PR#283）。計算値はメモリに残し、最新の master.json に対して書き直してから push する。

5読み取りは Pages か clone

raw.githubusercontent.com は全読み取り経路で使用禁止。状態の検証は clone ＋ git log で行う。

メンテナンスPR（仕様キーを変えるとき）

scoring_spec・system_status・granville_spec などの仕様キーを変えるときは、master.json を丸ごとコミットせず、Claude Code セッションに「最新 clone → 対象キーのみ置換（indent 検出）→ 差分行数と他キー同一性を検証 → PR」を指示する。対話セッション（Cowork 環境）は push できないため、置換後の JSON と指示文を納品し、Claude Code 側で実行する。マージ後、生成ページ（index.html／system.html）を再生成してコミットする。

python3 - <<'EOF' import json, re raw = open('master.json', encoding='utf-8').read() ind = len(re.search(r'\n( +)"', raw).group(1)) # 既存 indent の検出 d = json.loads(raw); keys = set(d) d['system_status'] = json.load(open('system_status_YYYYMMDD.json', encoding='utf-8')) assert set(d) == keys open('master.json', 'w', encoding='utf-8').write(json.dumps(d, ensure_ascii=False, indent=ind) + ('\n' if raw.endswith('\n') else '')) EOF git diff --numstat master.json # 数万行なら indent 不一致 → 中止
